## What failed, and the fix already applied

Build ran as a systemd user unit and died during the operator's interruption:

```
polaris-v115-build-nov22.service
  /home/ian/polaris-v101/scripts/build-astro.sh --version 115 \
    --pin 0f2f34e0004011136fa75bf43e215acc0c8b9fdb \
    --slug k01-camera-admission --summary docs/release-change-summary-v115-astro.json
Started 20:17:22Z, exited status=1/FAILURE at 20:26:40Z
```

Gate output (`out/k01-378-reviewed-20261122/build-v115-host.log`, workspace tree):

```
Pre-release gate summary: 25 passed, 1 failed, 1 skipped
Failed: container deterministic harness (exit 1; log: /tmp/prerelease-deterministic.log)
GATE: RED — do not stage/install the FwPkt until the failed checks pass.
BUILD FAILED (exit 1)
  WARNING: a partial FwPkt.zip exists -- do NOT use it
```

Root cause of the single red gate — a **test bug, not a product regression**:

- `tests/run_deterministic.sh:53` runs each test as `bash -c "set -euo pipefail; ./$t"`,
  so `./$t` honours the file's own shebang.
- `container/test_keepalive_required.sh` is `#!/bin/sh`; `/bin/sh` here is dash.
- Line 51 was `( exec -a "bash $ROOT/scripts/polaris-bt-keepalive.sh" sleep 60 ) &`.
  `exec -a` is a bashism → `51: exec: -a: not found` → exit 1 → whole gate RED.
- It passed on the host under bash, which is why it looked green locally and red in
  the harness. The harness is deliberately exercising POSIX sh, so the test must
  stay POSIX — re-shebang-ing it to bash would hide the class of bug it exists to
  catch.

Applied in `/home/ian/Documents/VSCodeProjects/BenroPolarisPatcher/container/test_keepalive_required.sh`:
replaced `exec -a` with a generated `$TMP/polaris-bt-keepalive.sh` wrapper, which puts
the same `polaris-bt-keepalive` string into `/proc/<pid>/cmdline` that the production
command does, so `detect()` is still exercised against the exact production shape.

Verified after the fix, in the workspace tree:

```
dash container/test_keepalive_required.sh   -> PASS, exit 0
tests/run_deterministic.sh test_keepalive_required.sh      -> 1 passed, 0 failed
tests/run_deterministic.sh test_camera_usb_supervisor.sh   -> 1 passed, 0 failed
tests/run_deterministic.sh (full)           -> 34 passed, 0 failed, 2 skipped, EXIT=0
```

The two prior failures are both green. `test_camera_usb_supervisor.sh` passes on the
host under bash and dash; its container-side failure was almost certainly collateral
from the same harness run — re-confirm inside the container on resume.

Ignore these when reading gate logs: lines like `FAIL: 1 mismatch(es) across 5 entries`
and `FAIL: 2 structural error(s)` are **negative controls inside passing tests**
(a manifest naming a missing file must fail). The `WARN: this single display version
moves 3 shipped components … registry entry must describe every one of them` is a
`WARN`, not a failure. Skips are prerequisite-gated and non-blocking:
`test_polaris_pentax_build_package.sh`, `test_source_input.sh`, plus the
firmwareInfo manifest gate (no stock `FwPkt.zip` in repo).
