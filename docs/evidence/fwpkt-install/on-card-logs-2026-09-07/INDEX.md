## Note on the wedged boot (Mlog_000062 + Clog_000062)

The 16:01 boot (gimbal-local) shows pgphoto respawning in a tight loop. The
companion log (Clog_000062) shows the stage2 loader reporting:

```
[stage2] FATAL early call to gp_port_new @slot=0x300000f0 before fill (slot unresolved / called in pre-fill window). Aborting cleanly.
[stage2]   last checkpoint reached: init: stubbed slots
[stage2] another pgphoto launch is already in progress; refusing duplicate
```

This is the **race-on-restart** failure mode of the loader. The first pgphoto
launch of a boot succeeds (slots get filled); subsequent restarts hit the race
because the slot table is freshly mmapped but the launch fires before dlopen
resolves all64 slots.

The boot before this one (Mlog_000061 / Clog_000061 at 12:48) shows the
patched build working fine ‚Äî Pentax K-3 Mark III connected, captures normal,
last line is a clean SP_GetNestFileList. So the patch itself is functional;
only the restart path is broken.

## Note on the 11:48 ‚Üí 14:37 gap

There is no Mlog/Clog between 11:48:49 (end of Mlog_000061) and the next
SP_LogPathInit at 11:48:49.578 (start of Mlog_000062). The Mlog_000061 file
mtime is Sep 7 12:48, Mlog_000062 mtime is Sep 7 16:01. **The pivot from
working to wedged happened sometime between 11:48 and 14:37 gimbal-local
(03:48‚Äì06:37 UTC)** ‚Äî i.e., during the window the user identified as "the
other agent made direct edits, reverted them, relating to SD backup".
