## Corruption warning — Mlog_000036.log

When the SD card was pulled from the gimbal, `polestar_app` (or its
logger thread) had an open write handle on `Mlog_000036.log`. The
FAT32 filesystem returned `EIO` (Linux errno 5, "Input/output error")
on read attempts beyond byte offset 32768 (the FS cluster boundary).
The captured copy is therefore only the first 32 KB of the original
~43.7 KB file — the trailing ~11 KB is unrecoverable from the
filesystem as mounted on the dev box.

This is consistent with the FAT32 spec's behaviour on a file that
was held open for write when the volume was unmounted: the data
clusters may have been deallocated, or the FAT chain may have been
left in a state that the kernel cannot follow cleanly. The
filesystem is otherwise undamaged — every other file on the card
read back without error and `md5sum` matched expected sizes.

**The ~11 KB missing from Mlog_000036 corresponds to log entries
written between ~16:01 and ~16:02 on 2026-09-05**, which is
exactly when the 812 trigger and the "Connection refused" boot
anomaly were observed in the 2026-09-04/05 session log. Those
lines may exist in the cached kernel page-cache on the device
itself, but are no longer recoverable from this card.
