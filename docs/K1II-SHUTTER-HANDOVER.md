**Independent source finding for reconnect.** The optional settle probe in stage2_loader.c reads pentaxpclvmode into an integer and tests for 1. The pinned driver getter in camlibs/ptp2/config.c returns a RADIO whose values are the strings on/off; the separate pentaxpclvkeep widget really is a toggle. A successful RADIO read therefore cannot reliably detect an already-on session this way. Some K-1 II reads of the mode widget also fail. Check the widget type, compare the returned string, and log unavailable distinctly. Gate that change with on/off/unavailable tests and verify the settle window on reconnect. This is a source defect; it has not been shown to cause steady-state lag.

**Decision after the current A/B.** If retained fetches are prompt but sparse at the documented interval, prioritize a bounded active-view cadence distinct from idle polling, with a single outstanding frame, setter priority, and existing transport-failure backoff. Choose a target only after measuring radio stability, SSH responsiveness and shutter response under load. If source frames complete but multipart delivery stalls, investigate the pgphoto publisher before changing PTP scheduling. If 8080 stays fresh but the phone lags, isolate IJK decode/render and scene-to-screen delay. Do not apply the PC frame rate as a firmware default.
