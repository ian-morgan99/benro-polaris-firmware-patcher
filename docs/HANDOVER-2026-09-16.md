## What the 2026-09-16 capture proved (and did not)

Full analysis: `docs/evidence/shutter-2026-09-16/SUMMARY.md`.

**Proven:**
- pgphoto is in a **restart loop**: `Clog.txt` = 84 repeated `[stage2] init`
  loader banners, `Clog-0102.txt` = 86 — each block completes
  `slots filled 64/64`, with **zero** PTP/camera traffic between them.
- The camera was **not on the USB bus** (fitted-but-off, loose cable, or
  camera powered off) — the documented restart-loop signature from
  `.github/skills/polaris-debugging/SKILL.md` §7.
- Mlog shows app-side keepalive churn only: two `code:266` connect/close
  cycles ~31 s apart (`id=28` 00:12:04, `id=29` 00:12:35), each followed by
  `SP_ClientCtxDel not find this is id`, plus a gimbal temperature push
  (`code:525`). No camera activity in Mlog.

**NOT proven (do not claim these):**
- ❌ That a shutter was set or a capture ran — no `state:` machine, no
  `captureImage`, no `SP_SET_SHUTTER`/`shutterString` anywhere.
- ❌ That the camera is healthy or unhealthy at PTP — it never reached PTP.
- ❌ That the restart loop is a loader bug — every block completes
  `slots filled 64/64`; the loop is the watchdog relaunching pgphoto
  because it exits at init (no camera to attach).

## Next steps (in order — do not skip)

1. **Prove it is the gimbal** before trusting any log:
   - `nmcli … | grep 48:E7:DA` (real `polaris_*` AP association),
   - `ip route get 192.168.0.1` → must go via the wifi dev,
   - `cat /app/FwVer` over SSH. Pingability alone proves nothing.
2. **Confirm the camera is on the USB bus:** `lsusb | grep 25fb` must show
   the Pentax (`25fb:0189` K-3 III / `25fb:0183` K-1 II). Empty = "no
   camera" — check power + cable seat first.
3. **Only after `lsusb` shows the camera**, re-run the shutter test and
   capture Clog/Mlog. A valid shutter result needs a `state:` machine
   (e.g. `1 -> 4 -> 2 -> 3 -> 5`) or an explicit `SP_SET_SHUTTER` /
   `shutterString` line — not just loader banners.
4. **Verify the preview backoff engaged** before trusting preview: grep Clog
   for `[stage2] preview-backoff: N consecutive failures (last ret=...)`.
   The init-time `slot -> shim` line only means the wrapper is installed,
   NOT that it fired.

## Rules that bind this handover (from AGENTS.md)

- **Documented skills are the source of truth** — read
  `.github/skills/polaris-debugging/SKILL.md` before touching the live
  device; `fwpkt-update-flow` is the ONLY sanctioned firmware install path.
- **SSH is read-only diagnostic.** No direct code/binary changes under
  `/app` as a supported fix; everything flows issue → owning repo → FwPkt
  build → SD-card install.
- **On-device camera test = direct CLI, not the daemon:** stop pgphoto, run
  `/app/bin/gphoto2` with `CAMLIBS`/`IOLIBS`/`LD_LIBRARY_PATH` from
  `/app/lib/stage2`, then restart the daemon and tail `/app/Clog.txt`.
- **Dual-path (#38) check on every flashed build:**
  `md5sum /app/lib/stage2/libgphoto2.so.6 /app/lib/libgphoto2.so.6` must
  match, and `/proc/<pgphoto>/maps` shows which core is actually loaded.
- **Repo routing (log the issue where the first divergence happens):**
  direct libgphoto2 SHA fails → `ian-morgan99/libgphoto2`; direct passes
  but packaged Stage-2/pgphoto path fails → this repo; both pass but app
  fails → `ian-morgan99/OpenPolaris`.
- **FwPkt provenance:** any new/received zip gets a registry row in
